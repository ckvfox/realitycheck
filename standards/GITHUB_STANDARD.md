# GitHub Standard

Hinweis fuer FPF 2.0: Die kanonische Quelle ist `standards/github.md`.

Dieses Dokument bleibt als historische Referenz aus 1.x bestehen.

## Branching

- Arbeit erfolgt ueber nachvollziehbare Feature-, Fix- oder Maintenance-Branches
- direkte Aenderungen auf dem Hauptbranch sollten bewusst und selten sein

## Commits

- Commits sind klein, klar und thematisch konsistent
- Commit-Nachrichten beschreiben die fachliche oder technische Aenderung eindeutig

## Issues

- Aufgaben, Fehler und Verbesserungen werden als Issues oder gleichwertige Tickets nachvollziehbar beschrieben
- kritische technische Schulden und bekannte Risiken sollen sichtbar sein

## Pull Requests

- Pull Requests enthalten Kontext, Scope, Risiken und Testhinweise
- Aenderungen an Security, Deployment oder Standards verdienen erhoehte Aufmerksamkeit

## Releases

- Releases fassen freigegebene Aenderungen nachvollziehbar zusammen
- Release-Notizen sollen auf CHANGELOG und relevante Migrationsschritte verweisen

## Tags

- Tags spiegeln Versionen eindeutig wider
- empfohlen ist semantische Versionierung mit konsistentem Tag-Schema
